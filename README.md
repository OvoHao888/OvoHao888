## 项目

### 1. [code-doctor](https://github.com/OvoHao888/code-doctor) · 自纠错多智能体代码诊断系统

`Python` `LangGraph` `FastAPI` `RAG/FAISS` `MCP` `Function Calling`

> 开发周期：**2026.04 起步（v1）→ 2026.10 重构为 v2**

提交一段有 bug 的 Python 代码，系统完成 静态分析 → 问题检测 → 代码修复 → **实际执行验证** → 生成报告的闭环，验证失败时带着执行错误回炉重试。

- **架构重构（v1→v2）**：把 v1 的 5 个 ReAct Agent 直线流程，改成 3 次结构化 LLM 调用 + 6 节点条件路由图，单请求耗时由约 68 秒降至约 25 秒。`legacy` 分支保留重构前的实现。
- **执行式验证**：用 `subprocess` 在隔离子进程中真实运行修复后的代码，以退出码与 stderr 作为**可证伪**判据，替代「让 LLM 自评修好了没有」。
- **确定性路由**：分支判断只读 state 上的结构化字段，不解析自由文本 —— 零 token 且可穷举单测。
- **评测体系**：27 条样本（19 正 + 8 负），F1 94.7%、干净样本误报率 0%。

### 2. [aireduce](https://github.com/OvoHao888/aireduce) · AI 文本润色平台

`Vue 3` `Vite` `FastAPI` `SQLAlchemy` `MySQL` `JWT`

> 开发周期：**2026.05 – 2026.06**

面向长文本改写的 AI 应用，含双模式处理链路、会员卡密体系与独立管理后台。

- **SSE 流式输出**：深度模式两阶段串行（学术润色 → 逻辑增强），全程流式下发增量内容，避免长文本等待白屏。
- **多用户隔离**：按用户维度缓存处理器实例并按活跃时间 LRU 淘汰；历史上下文超阈值自动压缩后再注入。
- **卡密并发安全**：兑换环节对卡密行加排他锁，保证并发下同一张卡只能成功兑换一次。
- **安全加固**：管理员口令与用户无盐 SHA-256 统一改为 bcrypt；CORS 由通配改为白名单；接口不再回显完整 API Key；硬编码密钥全部外置为环境变量。

### 3. [fruit-mall](https://github.com/OvoHao888/fruit-mall) · 水果商城系统

`Spring Boot 3` `MyBatis-Plus` `MySQL` `Redis` `Spring Security` `JWT` `Spring AI`

> 开发周期：**2025.02 – 2025.06**

前后端分离商城，含前台商城、管理后台与 AI 智能导购，共 20 张数据表。

- **两级缓存**：Caffeine 做进程内 L1、Redis 做 L2，读时逐级回填、增删改时两级同步失效；L1 的 TTL 刻意短于 L2 以兜底多实例脏读；Redis 异常时自动降级为仅用 L1，不影响业务。
- **鉴权链路排查**：定位并修复了一处**拦截器被自身排除规则抵消**导致的接口零鉴权问题，同时修掉口令哈希随接口返回。
- **AI 智能导购**：接入 Spring AI，用户以自然语言描述需求，由模型从候选商品中挑选匹配项返回；模型返回的 id 会按候选集做白名单校验。

## 一点说明

`code-doctor` 的 README 里写了我认为**必须如实交代**的边界：执行验证用的 `subprocess` 不是安全沙箱；RAG 的消融实验变量没有完全隔离，所以我**没有宣称 RAG 带来收益**，并因此默认关闭它。

我认为说清楚"我的方案在什么情况下不成立"，比宣称它处处成立更有价值。
